\section{Introduction}
\label{sec:intro}
Hybrid retrieval for retrieval-augmented generation (RAG) commonly combines the top $L$ results from dense and sparse retrievers using reciprocal rank fusion (RRF)~\cite{elastic,rrf}. A fixed window limits the number of entries accessed but also excludes contributions beyond that window. When a document appears in one ranked list but not in the other list's window, fusion assigns zero to the latter contribution. Yet absence from the window only means that the rank has not been observed; its contribution remains unknown. Replacing an unknown contribution with zero can change the output order even when the candidate set already contains every document in the top $K$ under RRF over the full ranked lists. Thus, $L$ is a retrieval-depth parameter that affects both retrieval quality and access cost.

In practice, $L$ can be selected using historical queries to balance quality and cost. However, RAG systems serving open-ended requests over evolving knowledge bases continually encounter new queries and updated corpora. Both changes alter the ranked lists and the positions of cross-channel contributions, making it difficult for a previously selected $L$ to preserve the original quality--cost tradeoff. Exact rank aggregation maintains bounds on unobserved contributions and accesses the ranked lists until the required results are determined~\cite{nra}. EAHR applies this approach to hybrid retrieval to obtain the exact top $K$ in order without a predefined truncation depth~\cite{eahr}. Nevertheless, the number of accesses required can vary sharply across queries: resolving competition at just a few positions can require accessing entries far down the ranked lists.

Because the same $K$ can require substantially different numbers of accesses, resource-constrained requests need to bound accesses directly rather than control cost indirectly through $K$. We take an access budget as input, defined as the maximum total number of sorted accesses to the two ranked lists, without specifying the output size in advance. Each sorted access retrieves the next entry from one list. The system incrementally certifies results and returns a certified prefix when the budget is exhausted: an initial segment guaranteed to match the RRF ranking over the full lists in both membership and order. Differences in query difficulty therefore translate into different output sizes, rather than additional accesses required to complete a fixed top-$K$ result.

To support retrieval under an access budget, we introduce DiBud (Direct Budgeting). DiBud incrementally computes the fused ranking, appending results whose ranks have been certified~\cite{lara} and directing subsequent accesses toward unresolved competition at later positions~\cite{snra}. When the budget is exhausted, it returns the current certified prefix. No $K$ is specified in advance; the output size is determined by the ranking information obtained within the budget.

We evaluate this approach through replays on five query sets and five corpus snapshots. We first examine fixed-depth transfer, then measure the access cost and incremental certification of exact top-$K$ results. Under equal budgets, we compare DiBud with balanced sorted access, including output distributions and changes across snapshots. Finally, calibration on disjoint queries quantifies the relevance retained and accesses saved relative to completing exact Top-20.
