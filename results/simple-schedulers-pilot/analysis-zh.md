# 无调参调度候选：本轮筛选结果

2026-09-10。没有更换论文方法；没有改动现有成稿或既有实验。只探索预算内精确前缀，不涉及已封存的缺失贡献补偿。

## 核心结论

本轮没有找到明显优于SNRA阻塞者原则的新通道选择公式。值得保留的是两个执行方向：利用两通道结构降低认证维护成本；在维护变轻后，以逐条决策换取小幅认证产出。不能把后者描述为全新的调度算法。

## 1. 已有证据先排除重复路线

旧记录已经尝试candidate、candidate-safe、周期混合SNRA、无参doubling-SNRA。五集合上这些变体整体没有超过blocker。原blocker在两个TREC集合上达到64条端点网格枚举的最高认证产出；这只说明该网格下剩余空间很小，不是连续分配或在线全局最优证明。

按单步最大上界缺口做选择也容易恢复原规则：最强已见竞争者占主导时，只有读取其缺失通道能降低它的上界；未见上界占主导时，选择最大上界下降量就是原回退。不能换个公式名字就当新方法。

## 2. 真实小样本筛选

五个查询集各按dataset/queryId的SHA-256排序选20条，共100条；预算128、256、512、1024、2048。无训练或系数搜索。沿用c=59、float32、UUID同分规则、相同完整RRF参考。认证结果逐位核对；报告上限100，达到100后停算（后续上限指标不再改变）。面积先逐查询计算，再集合等权汇总。

| 规则 | 归一化认证面积 | 相对原blocker64 | 查询面积胜/平/负 | 预算2048平均K（cap100） |
|---|---:|---:|---:|---:|
| 原blocker64 | 0.285650 | — | — | 46.54 |
| 逐条决策 | 0.290900 | +1.84% | 64 / 36 / 0 | 46.58 |
| 交接点小批次（最多64） | 0.290213 | +1.60% | 60 / 39 / 1 | 46.50 |
| 无批上限交接点跳读 | 0.277475 | −2.86% | 8 / 11 / 81 | 46.38 |
| 直接跳到当前认证边界 | 0.274213 | −4.00% | 2 / 11 / 87 | 45.43 |

面积收益主要来自较小预算处，并不意味着2048预算下多了很多结果。逐条决策在2048时仅增加0.04条（cap100），cap20为18.16→18.17。不要把1.84%的面积改写成所有预算下的产出提升。

失败例：TREC-DL2019查询182539，预算128，直接认证边界跳读分配为Dense1/Sparse127，仅认证1条；原blocker64在64/64处分配认证28条。NFCorpus查询PLAIN-1635同预算出现0对27。根据早期边界一次读太远，会失去中途利用新证据改选通道的机会。

交接点公式只描述在当前已见贡献不变时的边界位置，绝非对实际未来排名的预测或认证依据；所有输出均重新用真实读到的条目认证。

## 3. 最值得保留的结构：三个支持组

只在Dense出现：下界g(rD)，上界g(rD)+uS。
只在Sparse出现：下界g(rS)，上界g(rS)+uD。
两条通道均出现：上下界都为g(rD)+g(rS)。

每个组的上界有共同偏移，维护组内队首即可寻找下一候选和最强竞争者，排除当前候选时取后继；无需每次重算全体边界。实现用三个堆，并处理同分、移组和已经输出的文档。它完整复现原认证与通道选择。

这属于已有精确聚合思想的执行优化，不能直接声称独立算法novelty；NRA/LARA相关工作已有支持集分组与增量维护思想。本轮没有做新一轮文献新颖性审计。

## 4. 同环境配对计算开销

50条预选查询（各集10条）、串行、3次重复、方法顺序轮换。数字是每查询回放至预算2048或cap100的平均Python调度与认证时间；不含初始化、实际检索、索引、模型或网络。

| 实现 | 平均回放时间（ms） | 中位数（ms） |
|---|---:|---:|
| 原数组实现，blocker64 | 4.91 | 5.25 |
| 原数组实现，逐条 | 284.24 | 301.19 |
| 三组队首，blocker64 | 2.22 | 2.37 |
| 三组队首，逐条 | 13.19 | 14.81 |
| 三组队首，交接点小批次 | 14.08 | 13.75 |

三组维护使同输出的blocker64回放时间下降约54.8%。逐条决策的实现成本显著降低，但仍比原blocker64慢约2.68倍。交接点版本虽比逐条少做认证检查，边界计算抵消了这部分优势；当前不优先保留。

这些对比针对本仓库的参考回放实现，不证明比优化后的检索系统更快，更不等同于端到端RAG时延收益。

## 5. 给用户的候选顺序

1. **三组队首维护＋现有blocker64：优先保留。** 规则从两通道RRF结构直接得到，没有新超参数；同产出、较少计算。属于执行优化。
2. **三组队首维护＋逐条决策：保留为产出方向。** 每次读1条不需要调批大小；小样本面积有增益，但仍有额外计算成本，且SNRA通道选择不变。
3. **交接点小批次：留档，暂不优先。** 当前收益与开销均未体现出比逐条决策更好的整体取舍。

两种长跳规则暂时淘汰。不要为了凑“几个新算法”包装无效公式。要形成新的调度贡献，仍须找到通道选择本身的改进，而非仅改变维护实现或决策频率。
